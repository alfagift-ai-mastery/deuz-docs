Kustomisasi ​

Hampir semua penyesuaian dilakukan di deuz/config.yaml. Schema bawaan (default) sengaja dibuat cukup untuk kebanyakan tim. Fork schema hanya diperlukan untuk alur yang memang berbeda.

config.yaml lengkap ​

yaml
schema: default

# Bahasa isi dokumen. Kata kunci (SHALL, WHEN, THEN, ...) tetap bahasa Inggris.
language: id

# Peran aktif beserta nama tampilannya. Peran yang tidak ada di sini tidak aktif, dan artifact-nya di-skip.
roles:
  analyst: Product System Analyst
  designer: UI/UX
  frontend: SE Frontend
  backend: SE Backend
  qa: Tester
  business: Business stakeholders   # opsional: mengaktifkan gate persetujuan bisnis

# Opsional: mengganti pemilik sebuah artifact. Harus peran yang aktif.
# owners:
#   api-contract: [backend, analyst]

# Lokasi sumber kebenaran permanen. null = proyek tidak punya home itu.
homes:
  specs: deuz/specs
  design: design
  api: api/openapi.yaml

# Gambaran proyek untuk agent: stack, struktur folder, konvensi.
context: |
  Aplikasi perpustakaan. backend/ (Go), frontend/ (React), tests/ (Playwright).

# Instruksi tambahan per artifact.
# rules:
#   tasks-test:
#     - ID test mengikuti tests/README.md.

Peran ​

Daftarkan hanya peran yang benar-benar ada di tim. Artifact yang tidak punya pemilik aktif akan selalu di-skip.

TimPeran aktifAkibatnya
Lengkapanalyst, designer, frontend, backend, qaSemua artifact dipakai
Backend dan QA (API adalah produknya)analyst, backend, qaui-design dan tasks-frontend selalu di-skip
Dengan gate bisnis… + businessGate 1 dan Gate 2 aktif (lihat Persetujuan bisnis)

Nama tampilan peran muncul di output status, misalnya "Waiting: SE Backend".

Override owner ​

Untuk tim tanpa frontend yang API-nya dipakai tim lain, kontrak API bisa dimiliki backend bersama analyst:

yaml
owners:
  api-contract: [backend, analyst]

Override menggantikan owner sepenuhnya, termasuk owner kondisional. Jadi jangan meng-override proposal atau specs kalau ingin tetap memakai gate bisnis.

Homes ​

HomeIsinyaKapan konten masuk
specsSpec perilaku permanenSaat archive (delta digabung)
designFile desain, misalnya HTML per layarSebagai task terakhir tasks-frontend (atau saat archive kalau frontend di-skip)
apiDefinisi API, misalnya OpenAPISebagai task terakhir tasks-backend

Arahkan homes ke tempat yang sudah dipakai proyek, misalnya folder desain yang dibandingkan test visual, atau file OpenAPI yang di-generate. Dengan begitu tidak ada salinan kedua. Isi null kalau proyek tidak punya home tersebut.

Context dan rules ​

  • context dibaca agent setiap kali menulis dokumen. Isi dengan hal yang tidak bisa ditebak dari kode: stack, struktur folder, konvensi penamaan, dan istilah domain.
  • rules adalah instruksi tambahan untuk artifact tertentu, misalnya format ID test atau perintah verifikasi.

Keduanya untuk agent dan tidak pernah disalin ke dalam dokumen.

Bahasa ​

language menentukan bahasa isi dokumen. Yang tetap bahasa Inggris di semua bahasa: SHALL, MUST, GIVEN, WHEN, THEN, AND, header delta (## ADDED Requirements dan seterusnya), ### Requirement:, #### Scenario:, nama area di checklist, Type dan nilainya, Triage:, status pertanyaan beserta header kolom Status, dan penanda <!-- deuz:… -->. Judul bagian dari template boleh diterjemahkan.

Fork schema ​

Kalau tim butuh alur yang memang berbeda, misalnya peran tambahan atau artifact lain, salin schema bawaan ke deuz/schemas/<nama>/ (berisi schema.yaml dan templates/), lalu set schema: <nama> di config. Fork di proyek selalu menang atas schema bawaan dengan nama yang sama.

Sebelum melakukan fork, pastikan kebutuhannya tidak bisa diselesaikan dengan peran aktif, override owner, atau rules. Fork harus dirawat sendiri saat deuz diperbarui.

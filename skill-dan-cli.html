Skill dan CLI ​

deuz punya dua bagian, dan tempat memakainya berbeda:

Diketik diContohFungsi
SkillChat AI agent (Claude Code)/deuz:continue specsPekerjaan yang butuh penilaian: menulis dokumen, membaca kode, mengerjakan task
CLITerminal (dan dipanggil skill di belakang layar)deuz statusAturan yang harus pasti: status, kunci, konfirmasi, validasi, archive

Sehari-hari, kamu cukup memakai skill. Skill memanggil CLI dengan --json lalu menyajikan hasilnya. CLI dipakai langsung kalau ingin mengecek cepat, menjalankan di CI, atau bekerja tanpa agent.

Kalau CLI tidak ditemukan, skill menjalankan aturan di core/RULES.md sendiri dan memberi tahu bahwa hasilnya dihitung agent. Hasil CLI lebih bisa dipercaya, jadi pastikan bin/deuz sudah di-build.

Skill ​

SkillKapan dipakai
/deuz:initSekali per proyek: membuat deuz/config.yaml (peran, homes, bahasa, context)
/deuz:new <nama>Memulai work baru. Agent menanyakan tujuan, jenis work, dan hasil triage
/deuz:status [nama]Melihat status tiap dokumen, apa yang terkunci, dan siapa yang ditunggu
/deuz:continue [artifact]Menulis atau melanjutkan satu dokumen dari template dan instruksinya
/deuz:ready <artifact> --as <peran>[,<peran>]Mencatat konfirmasi pemilik. Untuk --as business, jalankan setelah rapat
/deuz:apply <tasks>Mengerjakan daftar task dan mencentang task yang terbukti selesai
/deuz:archive [nama]Menggabungkan delta ke spec permanen dan memindahkan work ke archive
/deuz:baseline <capability>Menulis spec permanen untuk perilaku yang sudah ada di kode

CLI ​

deuz [--root DIR] <command> [arguments] [--json]

  init --role id=Name... --home name=path|null... [--language id] [--schema default]
  new <work> [--date YYYY-MM-DD]
  status [work] [--write]
  instructions <artifact> [--work work]
  ready <artifact> --as role[,role] [--work work]
  validate [work]
  archive [work] [--dry-run] [--date YYYY-MM-DD] [--confirm-promote artifact]
  version
PerintahMenulis file?Keterangan
initYaMembuat deuz/config.yaml. Gagal kalau file sudah ada
newYaMembuat deuz/work/<nama>/.deuz.yaml. Nama harus kebab-case
statusTidakStatus, siapa yang ditunggu, progres task, langkah berikutnya
status --writeYaMenulis ulang .deuz.yaml dari kondisi sekarang tanpa mengubah konfirmasi. Dipakai untuk migrasi work lama atau setelah konflik merge
instructionsTidakBahan untuk agent menulis satu dokumen: template, instruksi, context, dokumen yang dibutuhkan
readyYaMencatat konfirmasi. Ditolak tanpa menulis apa pun kalau ada aturan yang dilanggar
validateTidakMemeriksa format dokumen, spec, coverage map, dan aturan gate
archiveYaMenggabungkan delta, promote, lalu memindahkan work. --dry-run untuk melihat rencananya dulu

Kode keluar: 0 berhasil, 1 ditolak oleh aturan, 2 salah pakai. Tanpa nama work, perintah memilih satu-satunya work aktif. Kalau ada beberapa, sebutkan namanya atau pakai --work.

CLI mencari deuz/config.yaml dari folder saat ini ke atas. --root menunjuk root proyek secara langsung.

Siapa menjalankan apa ​

PeranSkill yang paling sering dipakai
Analystnew, continue (proposal, specs), ready --as analyst, ready --as business setelah rapat, baseline
Designercontinue ui-design, ready --as designer
Backend / frontendcontinue api-contract, continue tasks-*, ready, apply
QAcontinue tasks-test, ready --as qa, apply tasks-test
Siapa sajastatus, archive

Di CI ​

deuz validate cocok dijalankan di pipeline. Kode keluar 1 berarti ada error, misalnya format spec salah, scenario yang belum dipetakan di coverage map, atau proposal yang melanggar aturan gate. Proposal yang sudah ready tidak dievaluasi ulang, jadi mengaktifkan aturan baru tidak membuat work lama gagal.

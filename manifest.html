Manifest work (.deuz.yaml, format 1) ​

Setiap folder work deuz berisi file .deuz.yaml. Selain menyimpan status work, file ini adalah manifest yang memungkinkan editor atau viewer menampilkan navigasi langkah demi langkah antar-dokumen sebuah work (proposal → specs → … → tasks) tanpa perlu tahu apa pun tentang schema deuz, dan tanpa frontmatter di dalam dokumen itu sendiri.

Halaman ini adalah kontrak untuk pembaca seperti itu. deuz yang menulis file ini; pembaca hanya membacanya.

Contoh ​

yaml
format: 1
schema: default
created: 2026-11-11
areas: [design, frontend, backend, api]
artifacts:
  proposal:       { title: "Proposal", requires: [], generates: "proposal.md", status: ready, ready_by: [analyst], hash: sha256:… }
  specs:          { title: "Specs", requires: [proposal], generates: "specs/**/spec.md", status: ready, ready_by: [analyst], hash: sha256:… }
  ui-design:      { title: "UI design", requires: [specs], generates: "ui-design/**", entry: "ui-design/README.md", status: ready, ready_by: [designer], hash: sha256:… }
  api-contract:   { title: "API contract", requires: [specs, ui-design], generates: "api-contract.md", status: draft, ready_by: [backend] }
  tasks-backend:  { title: "Backend tasks", requires: [specs, api-contract], generates: "tasks-backend.md", status: missing }
  tasks-frontend: { title: "Frontend tasks", requires: [specs, ui-design, api-contract], generates: "tasks-frontend.md", status: missing }
  tasks-test:     { title: "Test tasks", requires: [specs, ui-design, api-contract], generates: "tasks-test.md", status: skipped, reason: "no active owner" }

Pembaca bisa menampilkannya seperti ini:

reservations   1 Proposal ✓ › 2 Specs ✓ › 3 UI design ✓ › 4 API contract ◐ › 5 [Backend tasks · Frontend tasks · Test tasks –]

Field ​

FieldArti
formatVersi kontrak ini. Pembaca hanya memakai file jika mengenal versinya (saat ini 1).
artifactsSatu entri per artifact, sesuai urutan di schema. Key-nya adalah id artifact.
titleLabel untuk langkah tersebut.
requiresId artifact yang harus selesai sebelum artifact ini.
generatesPola file artifact, relatif terhadap folder work. * cocok di dalam satu segmen path (tanpa /); ** cocok dengan nol atau lebih segmen.
entryHanya ada untuk artifact berupa folder (generates diakhiri /**): file yang dibuka untuk artifact tersebut.
statusready, draft, missing, atau skipped, sesuai yang terakhir dicatat oleh CLI deuz.
reasonAlasan sebuah artifact berstatus skipped.
ready_by, hash, areas, schema, createdDipakai oleh deuz sendiri; pembaca boleh menampilkan ready_by.

Aturan untuk pembaca ​

  1. Temukan work-nya. Mulai dari file .md yang sedang dibuka, cari .deuz.yaml di folder file tersebut, lalu di setiap folder induknya, dan berhenti di root workspace. Pakai file itu hanya jika format adalah versi yang dikenal. Nama work adalah nama folder yang berisi .deuz.yaml.
  2. Urutkan langkahnya. Langkah sebuah artifact adalah 1 jika requires kosong; jika tidak, 1 + langkah tertinggi di antara artifact dalam requires-nya. Artifact dengan langkah yang sama ditampilkan bersama (misalnya sebagai tab), sesuai urutan di file.
  3. Temukan file-nya. File sebuah artifact adalah file di folder work yang cocok dengan generates, kecuali .deuz.yaml. Untuk navigasi, tampilkan hanya file .md. Buka entry jika ada; jika tidak, buka file pertama menurut path. Artifact yang punya beberapa file (misalnya specs, satu file per capability) menampilkan daftar file-file tersebut.
  4. Tampilkan statusnya. Tandai langkah yang berisi file yang sedang dibuka. Redupkan langkah berstatus skipped dan tampilkan reason-nya. Tampilkan status sesuai yang tercatat; jangan pernah menghitungnya ulang.
  5. Jaga kompatibilitas. Abaikan field yang tidak dikenal. Field yang hanya menambah informasi tidak mengubah format; perubahan arti sebuah field menaikkannya.

Kapan file ini ditulis ​

deuz new, deuz ready, dan deuz status --write menulis file ini. Archive ikut memindahkannya bersama folder work, sehingga work yang sudah di-archive tetap bisa dinavigasi. Work yang ditulis oleh deuz versi lama (tanpa format) mendapatkan field manifest lewat deuz status --write, tanpa mengubah konfirmasi apa pun.
